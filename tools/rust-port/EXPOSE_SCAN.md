The exact source loader scans all definition names for every exposed prefix. This candidate replaces only that callback-free scan with guarded native Rust. It preserves the source function text and executes the original `Object.keys`, `forEach`, property checks, lazy getter/setter creation, factory calls and recursive exposures.

The helper validates all inputs before any source-visible write: the captured string methods retain their original descriptors, the prefix is a primitive string, `keys` is a fresh extensible null-prototype object, and the current definition names are a dense array of primitive strings with ordinary own data descriptors. All guard misses execute the unchanged loop. Reads during guard validation use raw descriptors and never invoke getters. Each call inspects the current array; there is no stale prefix cache. Numeric property ordering remains the original `Object.keys` behavior. UTF-16 matching includes empty keys and unpaired surrogates.

Only the exact SHA-256 `9a6a28e97c4c79455e92d4ae1412375ca4c95f013494d0534b9cb779e1693911` is eligible. Helper-split functions are excluded. The function's variables stay environment-backed so the scan can preserve final `i` and `full`. The runtime guard's captured intrinsic values participate in GC tracing.

`node tools/rust-port/check-expose-scan.mjs` runs source comparisons with specialization both OFF and ON, including ordered factory effects and recursive exposure, mutable names, array/global accessors, poisoned string methods, object prefixes, inherited properties, UTF-16 and source text. A direct Rust test proves that the fast path actually accepts its intended domain and rejects mutation.

`node tools/rust-port/benchmark-expose-scan.mjs` compares both variants in one binary on 22,986 synthetic ordered names and 100 lazy properties. It reports the first scan and two later scans separately. These are loader component timings, not battles per second or complete battle qualification.
