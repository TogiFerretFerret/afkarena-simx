# Realistic 5v5 source CPU attribution

Command: `node tools/profile-realistic-battles.mjs --battles 10 --warmup 3`

Input: frozen seed 2026, five level-360 A5 heroes per camp, gear, SI30 and one beast each. Each measured battle completed with victory after 296 frames/ticks, 15,453 executed callbacks, and final source RNG bits `4216fd6c5e6c0000`. This repeats one scenario and is **not fidelity qualification**. The callback-only headless adapter excludes the complete source actor/effect frame lifecycle. Other agents were compiling/emitting during collection; the sampled 1.67 battles/sec is attribution evidence, not a clean throughput comparison.

The raw Inspector profile and JSON ranking are committed beside this note and in `benchmarks/results/`.

Inclusive percentages overlap and must not be summed. This is one composition: Puppeteer and Twins-specific updates are prominent, so a broad random corpus must guide final prioritization. The source `BattleEngine.tick` subtree accounts for 86.90% inclusive samples. Porting only RNG/math or optimizing cold table loading cannot remove that steady-state work.

Next implementation priority: connect the already differential-tested Rust unit/buff/attribute kernels to a single canonical battle state, with source fallback for unsupported mechanics. Avoid copying the whole JS state across the boundary each tick. A fast path may be used only where its source preconditions are checked and the complete ordered trace gate passes.

An opt-in guarded specialization of the nonescaping local parsed map was then measured with `--specialize 1`. It recorded 28,431 cache hits across warmup and measurement, zero fallbacks, and the same ten terminal counters/RNG bits. The parser disappeared from hot samples; the guard consumed 0.78% self samples. Elapsed sampled time was 5.60 seconds versus the earlier 5.99 seconds (about 7% higher sampled throughput), but different concurrent work prevents treating that difference as a clean speedup. The optimization remains opt-in pending complete battle trace qualification. Its exact source preconditions and 20k-query differential checks are recorded in `config/skill-cache-specialization.json`. Subsequent edits added cold source-proof hash checks; they do not change the measured hot function.
